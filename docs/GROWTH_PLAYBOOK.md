# برنامه رشد پس از انتشار

## هفته نخست

1. دامنه نهایی را متصل و `SITE_URL` را در Vercel ثبت کنید.
2. Google Search Console و Bing Webmaster Tools را تأیید کنید.
3. `sitemap.xml` را در هر دو سرویس ثبت کنید.
4. صفحه اصلی، نه پژوهش، صفحه داده، سه شاعر و سه موجودیت را برای ایندکس بررسی کنید.
5. کارت Open Graph را در LinkedIn آزمایش کنید.
6. یک Release با نسخه `6.0.0` در GitHub بسازید و فایل ZIP را ضمیمه کنید.

## ماه نخست

- هر هفته یک صفحه پژوهش یا موجودیت را در LinkedIn معرفی کنید.
- متن پست را به پرسش واقعی مخاطب تبدیل کنید؛ مثال: «آیا استعاره‌ها واقعاً می‌میرند؟»
- به‌جای لینک صفحه اصلی، URL دقیق همان موضوع را منتشر کنید.
- در توضیح پست یک عدد، یک محدودیت و یک دعوت به کاوش بیاورید.
- Queryهای Search Console را برای ساخت FAQهای جدید بررسی کنید.

## برنامه محتوایی پیشنهادی

- هفته ۱: تحول مضامین
- هفته ۲: زندگی استعاره‌ها
- هفته ۳: شبکه شاعران
- هفته ۴: هوش مصنوعی و تشخیص سده
- هفته ۵: اثر انگشت سبکی
- هفته ۶: جغرافیای تخیل
- هفته ۷: چرخهٔ عمر واژگان
- هفته ۸: انتساب شعر و پروندهٔ خیام
- هفته ۹ به بعد: شاعر، سده یا استعارهٔ منتخب

## صفحات دارای ظرفیت رشد بالا

- نام شاعر + «آمار شعرها»
- نام استعاره + «در شعر فارسی»
- «شاعران سده ... هجری»
- «هوش مصنوعی و تشخیص شاعر/سده»
- «تحلیل داده شعر فارسی»
- «دیتاست شعر فارسی»

## چرخه به‌روزرسانی

پس از تغییر داده یا تحلیل:

```bash
npm run data:generate
npm run data:attribution
npm run build
```

سپس:

- نسخه را در `package.json`، `CITATION.cff` و `codemeta.json` افزایش دهید.
- CHANGELOG را تکمیل کنید.
- تاریخ صفحات و sitemap را بازتولید کنید.
- URLهای تغییرکرده را در Search Console بررسی کنید.

## خط قرمزهای اعتبار علمی

- مرکزیت شبکه را رتبه ادبی معرفی نکنید.
- شباهت محاسباتی را تأثیر مستقیم ننامید.
- دورافتادگی آماری را انتساب نادرست ندانید.
- سده شاعر را تاریخ دقیق سرایش معرفی نکنید.
- فراوانی خام را بدون کنترل اندازه پیکره مقایسه نکنید.
